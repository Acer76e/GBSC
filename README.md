# Cloudflare Mobile

A Flutter Android app for managing Cloudflare zones — DNS records, IP access rules, development mode and cache purging — using the Cloudflare REST API.

## Features (v0.1)

- Sign in with either a scoped **API Token** or **Global API Key + email**
- List all zones with their status, with search
- **DNS Records**: view, create, edit and delete (A, AAAA, CNAME, TXT, MX, NS, SRV, CAA)
- **IP Access Rules**: list, create (Allow / Block / Challenge by IP, IP range, country or ASN) and delete
- **Zone Settings**: toggle Development Mode, purge the entire cache, view zone metadata
- Credentials stored in encrypted device storage (Android Keystore-backed via `flutter_secure_storage`)

## Getting an API Token

1. Go to https://dash.cloudflare.com/profile/api-tokens
2. Create a token with at least:
   - `Zone — Zone — Read`
   - `Zone — DNS — Edit`
   - `Zone — Zone Settings — Edit`
   - `Zone — Firewall Services — Edit`
   - `Zone — Cache Purge — Purge`
3. Paste the token into the app on first launch.

## Building the APK

A GitHub Actions workflow (`.github/workflows/build-apk.yml`) builds release APKs on every push to `main` and on manual dispatch.

To get an APK:

1. Push the repo to GitHub.
2. Open the **Actions** tab → run the **Build Android APK** workflow (or push a commit).
3. Once the run finishes, download the `cloudflare-mobile-apks` artifact — it contains:
   - `app-arm64-v8a-release.apk` (modern phones)
   - `app-armeabi-v7a-release.apk` (older 32-bit phones)
   - `app-x86_64-release.apk` (emulators / x86 tablets)
   - `app-release.apk` (universal fat APK)
4. Transfer the APK to your phone and install it (enable “Install from unknown sources”).

## Building locally

Requires Flutter ≥ 3.22 and Android SDK.

```bash
flutter create --project-name cloudflare_mobile --org com.acer76e --platforms=android --no-pub .
flutter pub get
flutter run                 # debug, on connected device
flutter build apk --release # release APK at build/app/outputs/flutter-apk/
```

The `android/` folder is generated by `flutter create` and **not** committed — keeps the repo lean. CI runs the same command before building.

## Security notes

- The APK is unsigned (debug-signed for development). For Play Store distribution you'd add a signing key — see `android/key.properties` setup in Flutter docs.
- Global API Key gives full account access. Prefer a scoped API Token whenever possible.
- Tokens never leave the device except in API requests to `api.cloudflare.com`.
